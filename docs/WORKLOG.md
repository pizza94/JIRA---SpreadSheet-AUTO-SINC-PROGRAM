# Jira Sheets Sync 개발 작업일지

## 작업 범위

- 기준 버전: v1.1.19
- 현재 버전: v2.0.0
- 목적: 신규·기존 체크리스트 자동화 안정화, SNAPSHOT 처리 개선 및 실행속도 단축

## 1. 입력 및 사용 흐름 정리

- Jira 서버 주소 입력란을 제거하고 Jira 로그인 버튼으로 단순화
- Google Sheets 링크만 입력하도록 변경
- 링크의 `gid`를 기준으로 대상 탭 이름 자동 감지
- 작업 유형과 등록할 SNAPSHOT을 필수 입력값으로 추가
- 작업 유형을 다음 두 가지로 분리
  - 신규 체크리스트에 최초 등록
  - 기존 체크리스트에 추가·업데이트
- 결과 저장 기본 위치를 Windows 바탕화면으로 변경
- 결과 파일을 성공·실패 내용을 모두 포함하는 TXT 한 개로 단순화

## 2. 신규 체크리스트 로직

- 복사된 시트에 이전 이슈가 남아 있어도 이슈 영역만 초기화
- 기존 SNAPSHOT 열은 한 개만 남기고 나머지 열 제거
- 남은 열의 헤더를 사용자가 입력한 `SNAPSHOT-숫자`로 변경
- 상단 Dashboard, 테스트 URL, Release Note 및 참고사항 영역 보존
- 첫 번째 이슈 행만 기준 양식 탭에서 생성
- 두 번째 이슈부터 완성된 첫 행의 양식과 드롭다운을 아래로 복사
- Jira 값 영역 `A~I`만 새 이슈 정보로 교체
- 신규 SNAPSHOT은 값이 선택되지 않은 빈 드롭다운으로 시작
- 참고사항여부는 `N` 드롭다운으로 시작

## 3. 기존 체크리스트 및 SNAPSHOT 로직

- 입력한 SNAPSHOT 헤더가 있으면 해당 열 재사용
- 사용할 빈 작업 열이 있으면 새 열을 만들지 않고 재사용
- 필요한 경우에만 참고사항여부 왼쪽에 SNAPSHOT 열 추가
- 기존 Jira 번호가 있으면 중복 행을 만들지 않고 해당 행 업데이트
- 신규 Jira는 준비된 빈 행부터 사용하고, 빈 행이 없을 때만 행 삽입

### SNAPSHOT 승계 규칙

| 이전 값 | 새 SNAPSHOT |
|---|---|
| PASS | 테스트완료 |
| 보류 | 그대로 승계 |
| 반려 | 그대로 승계 |
| 현장확인 | 그대로 승계 |
| 테스트제외 | 그대로 승계 |
| 테스트중 | 그대로 승계 |
| 개발중 | 그대로 승계 |
| 테스트완료 | 그대로 승계 |
| 재개발·재개발요청·추가이슈 | 빈 드롭다운 |
| 신규 이슈 | 빈 드롭다운 |

## 4. 드롭다운 오류 분석 및 수정

### 발견된 문제

신규 행의 SNAPSHOT 값은 빈값으로 저장됐지만 실제 셀에는 드롭다운 데이터
유효성이 남지 않는 문제가 있었습니다.

### 원인

Google Sheets에서 값이 들어 있는 드롭다운에 `Delete`를 누르면 값만 제거되지만,
이미 비어 있는 드롭다운에 `Delete`를 누르면 데이터 유효성까지 제거되는 동작을
확인했습니다.

기존 로직은 빈 드롭다운을 복사한 뒤 행 전체에 다시 `Delete`를 수행하고
있었습니다.

### 수정

- 각 대상 탭에서 `드롭다운 샘플` 문구를 동적으로 탐색
- 문구 바로 아래의 공통 샘플을 SNAPSHOT과 참고사항에 사용
- 고정된 셀 주소를 사용하지 않도록 변경
- 빈 드롭다운은 샘플을 그대로 복사하고 추가 `Delete`를 하지 않도록 수정
- 참고사항은 같은 샘플을 복사한 뒤 신규 `N`, 기존 `Y/N` 유지

## 5. 대상 탭 보호

- 모든 쓰기 작업 전에 다음 정보를 확인
  - 스프레드시트 ID
  - 링크의 `gid`
  - 현재 활성 탭 이름
- 세 정보 중 하나라도 다르면 작업 중단
- 기준 양식 탭은 읽기 원본으로만 사용
- 동일 Jira 번호가 여러 행에 있으면 자동 작업 중단
- 저장 후 CSV를 다시 조회하여 실제 반영 여부 검증
- 읽기 전용 시트는 성공으로 처리하지 않음

## 6. 성능 개선

| 항목 | 개선 내용 |
|---|---|
| Jira 조회 | 최대 4건 병렬 조회 |
| 신규 행 생성 | 첫 행만 기준 양식 생성 후 나머지 행은 첫 행 복사 |
| 하이퍼링크 | Jira 정보와 링크 수식을 한 번에 입력 |
| 시트 재조회 | 최신 조회 데이터를 다음 이슈 처리에 재사용 |
| SNAPSHOT 변경 | 값이 다른 셀만 수정 |
| 연속 셀 처리 | 변경값을 연속 범위 단위로 일괄 입력 |
| 드롭다운 보정 | 실패한 셀만 실제 드롭다운에서 선택 |
| 저장 확인 | 최초 대기시간을 2초에서 0.5초로 단축 |

### 실측 결과

3개 Jira 이슈 기준으로 측정했습니다.

| 작업 | 개선 전 | v2.0.0 | 결과 |
|---|---:|---:|---:|
| 신규 체크리스트 | 약 50.8초 | 약 37.5초 | 약 26% 단축 |
| 기존 체크리스트 SNAPSHOT 생성 | 약 36.9초 | 약 26.1초 | 약 29% 단축 |
| 동일 SNAPSHOT 재실행 | - | 약 22.5초 | 중복 없이 업데이트 |

Jira 조회 자체는 약 40~50ms였으며, 대부분의 실행시간은 Google Sheets UI 조작과
저장 결과 재조회에서 사용되는 것을 확인했습니다.

## 7. 최종 검증

- 신규 체크리스트 3건 등록 성공
- 기존 체크리스트 SNAPSHOT 추가·업데이트 성공
- Jira 번호 하이퍼링크 수식 확인
- SNAPSHOT-1, SNAPSHOT-2 및 참고사항 셀의 실제 드롭다운 메뉴 확인
- 신규 참고사항 기본값 `N` 확인
- 다른 탭에 쓰기 작업이 발생하지 않는 대상 탭 보호 확인
- 테스트 종료 후 Jira 로그인 세션 삭제 확인

## 8. 공개 저장소 처리

- 실제 사내 Jira 주소는 `http://jira.example.local:8079` 예시값으로 치환
- 실제 Google Sheets ID는 `YOUR_SPREADSHEET_ID` 예시값으로 치환
- 로그인 세션, 결과 파일, EXE 및 빌드 중간 폴더 제외

## 9. 날짜별 작업결과 이력

- 작업결과 파일을 `Jira-Sheets-작업결과-YYYY-MM-DD.txt` 형식으로 날짜별 관리
- 같은 날짜의 성공·실패 결과를 한 파일에 함께 보존
- 실행할 때 기존 결과를 덮어쓰지 않고 새 결과를 파일 맨 위에 추가
- 날짜가 바뀌면 새로운 일자 파일을 자동 생성
- 한국 시간 기준 날짜 경계와 최신순 누적 동작을 자동 테스트로 검증

## 10. Jira 제목 끝 공백으로 인한 저장 검증 실패 수정

- Jira 제목 끝에 공백이 있는 MS-12872에서 실패 현상을 실제 시트로 재현
- Google Sheets가 붙여넣을 때 제목의 끝 공백을 제거하는 것을 확인
- Jira 예상값과 Sheets 실제값 비교 시 앞뒤 공백을 정규화하도록 변경
- 검증 실패 시 필드별 예상값과 실제값을 오류 메시지에 표시
- 실패 원인 요약에서 소스 코드 줄 대신 실제 `Error:` 메시지를 우선하도록 개선
- 동일 14건 재시험 성공 및 신규 MS-12875·MS-12879 행 추가 확인
