# Jira → Google Sheets 자동화

사내 Jira 이슈 목록을 조회하고, 지정한 Google Sheets 탭의 기존 양식에 맞춰
일괄 등록하는 Playwright 기반 자동화입니다.

## 작업 유형과 SNAPSHOT 지정

동기화를 실행할 때 다음 두 항목을 반드시 입력합니다.

- 작업 유형
  - `신규 체크리스트에 최초 등록`
  - `기존 체크리스트에 추가·업데이트`
- 등록할 SNAPSHOT
  - `SNAPSHOT-3`, `SNAPSHOT-6`, `SNAPSHOT-11` 형식

입력한 SNAPSHOT 헤더가 이미 있으면 해당 열을 사용합니다. 같은 헤더가 없고
`SNAPSHOT-` 빈 작업 열이나 테스트자와 참고사항여부 사이의 빈 열이 있으면 그
열의 헤더를 입력값으로 변경합니다. 사용할 빈 열도 없을 때만 참고사항여부
왼쪽에 새 열을 추가합니다.

신규 체크리스트 모드는 복사한 시트의 이슈 영역 값만 초기화하고, 기존 SNAPSHOT
열은 가장 왼쪽 열 하나만 남긴 뒤 나머지를 삭제합니다. 남긴 열의 헤더는 입력한
`SNAPSHOT-숫자`로 변경하며, SNAPSHOT과 참고사항 사이의 빈 열도 제거합니다.
상단 안내문, 테스트 URL, Release Note, 참고사항
영역은 보존합니다. 입력하지 않은 일정은 데드라인 `-`, 테스트 시작일·종료일
빈값으로 초기화합니다. 신규 이슈 행은 `4.2.2.59 (LS증권)` 탭에서 확인한 기본
이슈 행 양식과 유형 색상을 사용합니다. SNAPSHOT·참고사항 드롭다운은 작업
대상 탭 Dashboard 오른쪽의 `드롭다운 샘플` 셀 바로 아래에 둔 공통 샘플을
복사하여 모든 신규 행에 적용합니다. 선택한 SNAPSHOT은 빈 드롭다운,
참고사항여부는 `N` 드롭다운으로 시작합니다.
신규 이슈가 여러 건이면 첫 행만 기준 양식으로 만들고, 두 번째 행부터는 완성된
첫 행의 서식과 드롭다운을 아래로 복사한 뒤 Jira 값 영역만 교체합니다.

기존 체크리스트 모드는 현재 이슈와 선택값을 보존하면서 기존 등록·업데이트 및
SNAPSHOT 승계 규칙을 그대로 적용합니다.

## v1.1.19 → v2.0.0 성능 개선

| 개선 항목 | v1.1.19 | v2.0.0 |
|---|---|---|
| Jira 조회 | 순차 조회 중심 | 최대 4건 병렬 조회 |
| 신규 행 생성 | 이슈마다 기준 양식 탭을 다시 열어 복사 | 첫 행만 기준 양식 생성 후 나머지 행은 첫 행 복사 |
| Jira 정보 입력 | 기본 정보와 하이퍼링크를 별도로 입력 | Jira 정보와 하이퍼링크를 한 번에 입력 |
| 시트 재조회 | 처리 단계마다 반복 조회 | 최신 조회 결과를 다음 이슈 처리에 재사용 |
| SNAPSHOT 반영 | 셀마다 개별 입력 | 변경이 필요한 연속 셀을 범위 단위로 일괄 반영 |
| SNAPSHOT 승계 | 전체 셀 재입력 | 기존값과 다른 셀만 변경 |
| 빈 드롭다운 생성 | 복사 후 Delete 처리 | Dashboard의 빈 드롭다운 샘플을 그대로 복사 |
| 저장 확인 | 최초 확인까지 2초 대기 | 0.5초 후 확인 시작하고 실패할 때만 재시도 |

3개 Jira 이슈 기준 실측 결과:

| 작업 | 개선 전 | v2.0.0 | 개선율 |
|---|---:|---:|---:|
| 신규 체크리스트 작성 | 약 50.8초 | 약 37.5초 | 약 26% 단축 |
| 기존 체크리스트 SNAPSHOT 생성 | 약 36.9초 | 약 26.1초 | 약 29% 단축 |
| 동일 SNAPSHOT 재실행 | - | 약 22.5초 | 중복 생성 없이 업데이트 |

## Windows 데스크톱 프로그램

팀원은 명령어 대신 Electron GUI를 사용할 수 있습니다.

### v2.0.3 변경 사항

- Jira 상태 기반 SNAPSHOT 반영 규칙을 추가했습니다.
- 현재 실행에 입력한 기존 이슈 중 이전 SNAPSHOT 값이 `테스트중`, `개발중`,
  `재개발`, `재개발요청`, `추가이슈`인 이슈만 대상입니다.
- Jira 상태가 `작업 진행중`, `개발 진행중`, `개발 예정`, `재 개발 요청`, `00.Backlog`이면 새
  SNAPSHOT 드롭다운을 `개발중`으로 설정합니다.
- Jira 상태가 `보류` 또는 `반려`이면 새 SNAPSHOT 드롭다운을 각각 `보류` 또는
  `반려`로 설정합니다.
- Jira 상태가 `개발 완료`이거나 그 외 상태이면 새 SNAPSHOT은 빈 드롭다운으로
  설정합니다. 신규 행과 이번 실행에 입력하지 않은 기존 이슈는 영향을 받지 않습니다.
- 입력 목록에서는 `MS-`, `QS-`, `IRD-`, `MDM-`, `MDMS-`, `MSUI-`, `QSUI-`,
  `MDMT-` 형식의 Jira 번호만 추출합니다.

### 개발 환경에서 실행

```powershell
npm.cmd install
npm.cmd run app
```

### Windows 무설치 EXE 생성

```powershell
npm.cmd run dist:win
```

완성된 프로그램은 `dist/Jira-Sheets-Sync-2.0.0.exe`에 생성됩니다. 팀원에게는
이 EXE만 전달하면 됩니다.

프로그램 사용 순서:

1. `Jira 로그인`을 누르고 열린 Google Chrome에서 각자 로그인
2. Jira 번호 목록 입력
   - 분류, 대괄호, 제목이 포함된 목록을 붙여넣어도 Jira 번호만 자동 추출
3. 작업할 탭을 연 상태의 Google Sheets 링크 입력
4. 결과 저장 폴더 확인
   - 기본값은 Windows 바탕화면
   - 경로를 직접 입력하거나 `폴더 선택` 버튼으로 변경 가능
5. 필요한 경우 테스트 배포일정·시작일·종료일을 `YYYY.MM.DD`로 입력
6. `조회 및 시트 반영` 실행
7. 우측 결과 표와 상세 로그에서 성공 여부 확인

Jira 서버 주소와 Google Sheets 링크 옆에는 기본값이 표시됩니다. `복사` 버튼을
누르면 클립보드에 복사되는 동시에 해당 입력칸에 주소가 자동 입력됩니다.
Google Sheets 링크에는 작업할 탭의 `gid`가 포함되어야 하며, 프로그램이 링크의
`gid`를 기준으로 대상 탭과 탭 이름을 자동 확인합니다.

각 팀원 PC에는 Google Chrome이 설치되어 있어야 합니다. 프로그램 실행 중에는
로그인 쿠키와 입력 설정을 각 PC의 앱 데이터 폴더에 임시 저장하며, 프로그램을
종료하면 로그인 세션과 입력값을 삭제합니다. 실행 결과 TXT는 유지됩니다.
`결과 폴더` 버튼은 화면에 현재 입력된 저장 경로를 엽니다.

## 앞으로의 대화 흐름

1. 사용자가 Jira 번호 목록을 전달합니다.
   - 예: `MS-12847, MS-12848, MS-4395`
2. Codex가 Jira 로그인 세션을 확인합니다.
   - 세션이 없거나 만료됐으면 Playwright 로그인 창을 엽니다.
   - 사용자는 브라우저에서 직접 로그인합니다.
   - 비밀번호는 스크립트가 읽거나 저장하지 않습니다.
3. Codex가 각 Jira 이슈에서 다음 정보를 확인합니다.
   - 유형, Jira 번호, 고객사, 제목, 상태, 중요도, 담당자
   - 고객사는 Jira 제목과 상위 이슈, 시트명, 라벨·컴포넌트·프로젝트를 참고합니다.
   - 같은 고객사가 시트에 있으면 기존 표기를 재사용합니다.
4. Codex가 작업할 탭을 연 상태의 Google Sheets 링크를 요청합니다.
5. 대상 탭을 이름으로 찾아 다음 규칙으로 입력합니다.
   - 새 이슈: 헤더 아래에 번호가 준비된 빈 이슈 행이 있으면 첫 빈 행부터 입력
   - 기존 이슈가 하나도 없으면 번호가 없어도 헤더 바로 아래 빈 행부터 입력
   - 준비된 빈 이슈 행을 모두 사용한 뒤에만 마지막 이슈 아래에 새 행 삽입
   - 새 행 삽입 시 아래쪽 빈 공간과 참고사항 영역을 함께 밀어 기존 간격 유지
   - 신규 체크리스트: 이슈 영역 값 초기화, 헤더가 비어 있는 열까지 정리하여
     SNAPSHOT 열 한 개만 유지하고 입력한 SNAPSHOT 헤더 적용
   - 기본 행·유형 색상은 `4.2.2.59 (LS증권)`, SNAPSHOT·참고사항 드롭다운은
     현재 대상 탭 Dashboard의 `드롭다운 샘플` 아래 공통 샘플을 찾아 복사
   - 기존 이슈: 중복 행을 만들지 않고 핵심 필드만 갱신
   - 번호: 이슈 순서에 맞춰 자동 입력
   - Jira 번호: 실제 Jira 이슈로 연결되는 하이퍼링크 수식 적용
   - 서식: 기존 행의 테두리·정렬을 복사하고 신규 체크리스트의 유형 색상은
     기준 시트의 동일 유형(버그·개선·부작업·새 기능) 셀에서 각각 복사하며,
     상단 집계표 배경색은 복사하지 않음
   - SNAPSHOT: 사용자가 입력한 헤더를 정확히 선택하고, 없을 때만 빈 작업 열을
     재사용하거나 참고사항여부 왼쪽에 새 열을 만든 뒤 기존 승계 규칙 적용
   - 이전 SNAPSHOT 값이 `PASS`이면 새 SNAPSHOT에서는 `테스트완료`로 승계
   - 현재 입력한 기존 이슈의 이전 값이 `테스트중`, `개발중`, `재개발`,
     `재개발요청`, `추가이슈`이면 Jira 상태에 따라 `개발중`, `보류`, `반려`
     또는 빈 드롭다운으로 설정
   - 그 외 SNAPSHOT 값은 기존 승계 규칙을 유지
   - 신규 이슈: 과거 SNAPSHOT 셀은 `진한 회색 3` 비활성 영역으로 처리하고,
     새 SNAPSHOT 셀은 데이터 유효성 검사를 유지한 빈 드롭다운으로 시작
   - 이전 값은 CSV로 정확히 식별하며, 변환이 필요한 연속 셀은 범위 단위로
     한 번에 반영
   - 저장 검증에서 누락된 셀만 실제 드롭다운 항목을 선택하여 보정
   - 새 SNAPSHOT 헤더는 사용자가 입력한 `SNAPSHOT-숫자` 값으로 작성
   - 드롭다운: `SNAPSHOT`과 `참고사항여부(Y/N)` 유효성 검사 복사
   - 참고사항여부: 기존 `Y/N`은 유지하고 신규 행은 기본값 `N`
   - 테스트자 값: Jira에서 확정할 수 없으면 비워둠
6. 선택 입력한 테스트 배포일정·시작일·종료일을 시트 상단 일정 영역에 반영합니다.
7. CSV 재조회로 저장 결과를 검증합니다.

## 최초 준비

```powershell
npm.cmd install
npm.cmd run jira:login
```

열린 Playwright 창에서 Jira에 직접 로그인하면 세션이
`playwright/.auth/jira.json`에 저장됩니다. 이 파일은 `.gitignore`에 포함되어
있으며 외부에 공유하면 안 됩니다.

## 일괄 동기화 명령

```powershell
npm.cmd run sync -- `
  --issues MS-12847,MS-12848,MS-4395 `
  --sheet-url "https://docs.google.com/spreadsheets/d/.../edit?gid=123#gid=123" `
  --work-mode existing `
  --snapshot-name SNAPSHOT-3
```

자동화는 링크의 `gid`를 기준으로 대상 탭을 선택하고 실제 활성 탭의 이름을
자동 감지합니다. `gid`가 없거나 링크가 가리킨 탭을 확인할 수 없으면 다른 탭에
임의로 작성하지 않고 작업을 중단합니다.

## 저장 결과

기본 저장 위치는 Windows 바탕화면이며, 프로그램에서 직접 경로를 입력하거나
폴더 선택 창으로 변경할 수 있습니다.

- `Jira-Sheets-작업결과-YYYY-MM-DD.txt`: 해당 날짜의 성공·실패 이력을
  최신 실행이 위에 오도록 누적 저장

같은 날짜에 여러 번 실행해도 이전 결과를 덮어쓰지 않습니다. 날짜가 바뀌면
새로운 날짜 파일을 생성하며, 각 파일 안에서는 가장 최근 실행이 위에 표시됩니다.

## 안전 규칙

- Jira와 Google 비밀번호는 자동화 코드에 입력하지 않습니다.
- 같은 Jira 번호가 여러 행에 있으면 자동 수정을 중단합니다.
- 모든 값 입력·붙여넣기·삭제·행/열 추가·색상 변경 직전에 최초 링크의
  스프레드시트 ID, `gid`, 활성 탭 이름을 다시 확인합니다. 하나라도 다르면
  즉시 중단하여 다른 시트 탭을 변경하지 않습니다.
- 기본 행·유형 색상 기준 시트는 셀 복사를 위한 읽기 원본으로만 사용하고 값을
  수정하지 않습니다. 드롭다운은 현재 작업 대상 탭 안의 Dashboard 샘플만
  사용합니다.
- 준비된 빈 이슈 행이 없으면 새 행을 삽입하며 기존 내용을 덮어쓰지 않습니다.
- 기존 행 업데이트 시 테스트자와 참고사항여부 `Y/N`은 보존합니다.
- 신규 행의 참고사항여부는 `N`으로 설정합니다.
- 이전 SNAPSHOT 값이 `PASS`인 기존 이슈는 새 SNAPSHOT에서 `테스트완료`로
  자동 변경합니다.
- 현재 입력한 기존 이슈의 이전 SNAPSHOT 값이 `테스트중`, `개발중`, `재개발`,
  `재개발요청`, `추가이슈`이면 Jira 상태를 기준으로 새 SNAPSHOT 값을 결정합니다.
  `작업 진행중`, `개발 진행중`, `개발 예정`, `재 개발 요청`, `00.Backlog`는 `개발중`, `보류`는
  `보류`, `반려`는 `반려`, 그 외 상태는 빈 드롭다운입니다.
- 새 SNAPSHOT 값은 빈 행을 포함한 실제 행 위치를 유지한 채 연속 변경 구간별로
  일괄 반영하여 `PASS → 테스트완료` 값이 밀리거나 누락되지 않게 처리합니다.
- 드롭다운 값은 CSV 재조회로 검증하고, 반영되지 않은 셀만 실제 드롭다운에서
  해당 항목을 선택합니다. 최대 2회 보정 후에도 다르면 셀 주소와 예상값을
  오류 로그에 남깁니다.
- Jira 서버 주소는 사내 고정 주소를 사용하며 화면에는 로그인 버튼만 표시합니다.
- Jira 이슈는 최대 4건씩 병렬 조회하며 입력 순서는 그대로 유지합니다.
- 시트 검증에서 받은 최신 행 데이터를 다음 이슈 처리에 재사용해 불필요한 CSV
  재조회를 줄입니다.
- 새 SNAPSHOT 열 복사 후 이미 원하는 값과 같은 셀은 재입력을 생략하고 실제로
  다른 셀만 변경합니다.
- 작업결과 TXT에 처리시간과 이슈별 결과를 간단히 기록합니다.
- Google Sheets 반영 지연을 고려해 새 SNAPSHOT 열과 승계 값을 충분히 기다린 뒤
  Jira 이슈 행 기준으로 재검증합니다.
- Google Sheets 링크가 조회 전용이면 저장 검증이 실패하며 변경 완료로 보고하지
  않습니다.
